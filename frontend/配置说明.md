# 前端环境变量配置说明

## API Key 加密配置

前端使用 AES 加密算法对 API Key 进行加密存储，密钥配置通过环境变量管理。

### 配置步骤

1. **创建环境变量文件**
   
   在项目根目录（`/frontend`）下创建 `.env` 文件：
   ```bash
   touch .env
   ```

2. **添加加密配置**
   
   在 `.env` 文件中添加以下配置：
   ```properties
   # API Base URL
   VITE_API_BASE_URL=http://localhost:19080/agt/api
   
   # API Key 加密配置
   # 注意：这些值必须与后端 application.yml 中的配置保持一致
   VITE_ENCRYPTION_SECRET_KEY=AI-ATG
   VITE_ENCRYPTION_IV=AI
   ```

3. **生产环境配置**
   
   ⚠️ **重要提示**：
   - 默认的密钥和 IV 仅供开发测试使用
   - **生产环境必须修改为强密钥**
   - 确保前后端使用相同的密钥配置
   - 密钥长度：`SECRET_KEY` 必须是 32 字节，`IV` 必须是 16 字节

4. **重启开发服务器**
   
   修改 `.env` 文件后，需要重启开发服务器：
   ```bash
   npm run dev
   ```

### 密钥要求

- **SECRET_KEY**（密钥）：
  - 长度：32 字节（256 位）
  - 格式：任意字符串，确保足够复杂
  - 示例：`AI-ATG`（32字符）

- **IV**（初始化向量）：
  - 长度：16 字节（128 位）
  - 格式：任意字符串
  - 示例：`AI-ATG`（16字符）

### 与后端配置保持一致

前端的加密配置必须与后端 `application.yml` 中的配置保持一致：

**后端配置位置**：`backend/src/main/resources/application.yml`
```yaml
encryption:
  secret-key: AI-ATG  # 与 VITE_ENCRYPTION_SECRET_KEY 一致
  iv: AI-ATG  # 与 VITE_ENCRYPTION_IV 一致
```

### 故障排除

如果遇到加密/解密失败的问题，请检查：

1. ✅ 前后端密钥配置是否完全一致
2. ✅ 密钥长度是否符合要求（SECRET_KEY: 32字节，IV: 16字节）
3. ✅ 环境变量是否正确加载（检查 `import.meta.env` 对象）
4. ✅ 修改 `.env` 文件后是否重启了开发服务器

### 安全建议

1. 📌 **不要将 `.env` 文件提交到版本控制系统**（已在 `.gitignore` 中配置）
2. 📌 为不同的环境（开发、测试、生产）使用不同的密钥
3. 📌 定期轮换生产环境的密钥
4. 📌 使用密钥管理服务（如 AWS KMS、Azure Key Vault）管理生产环境密钥
