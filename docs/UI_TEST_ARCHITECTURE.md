# UI自动化测试架构方案

## 架构对比

### 方案一：服务端执行模式（当前实现）

```
┌─────────────┐      ┌─────────────────────────────┐
│  客户端浏览器  │ ───→ │  后端服务器 (Linux)          │
└─────────────┘      │  - 安装Chrome/Firefox       │
                     │  - 安装WebDriver            │
                     │  - 启动浏览器执行测试         │
                     │  - 生成报告和截图             │
                     └─────────────────────────────┘
```

**适用场景**：
- 集中化管理
- 标准化测试环境
- CI/CD集成

**优点**：
- ✅ 集中管理，无需客户端配置
- ✅ 环境统一，结果可靠
- ✅ 便于CI/CD集成

**缺点**：
- ❌ 服务器需要安装浏览器
- ❌ 服务器资源消耗大
- ❌ 无法测试客户端特定环境

---

### 方案二：客户端代理模式（推荐）

```
┌─────────────┐      ┌─────────────────┐      ┌──────────────────┐
│  客户端浏览器  │ ───→ │  后端服务器      │ ───→ │  客户端测试代理   │
└─────────────┘      │  - 任务调度      │      │  - 接收测试任务   │
                     │  - 结果收集      │      │  - 启动本地浏览器  │
                     │  - 报告生成      │      │  - 执行UI操作     │
                     └─────────────────┘      │  - 上传结果       │
                                              └──────────────────┘
                                                      ↓
                                              ┌──────────────────┐
                                              │  本地浏览器        │
                                              │  (Chrome/Firefox) │
                                              └──────────────────┘
```

**适用场景**（您的需求）：
- 测试人员在本地执行测试
- 测试不同操作系统环境
- 分散服务器负载

**优点**：
- ✅ 服务器不需要安装浏览器和WebDriver
- ✅ 分散负载到客户端
- ✅ 可以测试真实的客户端环境（Windows/Mac）
- ✅ 支持多客户端并发执行

**缺点**：
- ❌ 需要客户端安装代理程序
- ❌ 客户端需要保持在线
- ❌ 环境差异可能导致结果不一致

---

```

│  客户端浏览器  │ ───→ │  后端服务器      │ ───→ │  Selenium Hub     │
└─────────────┘      │  - 任务调度      │      │  - 任务分发       │
                     └─────────────────┘      └──────────────────┘
                                                       │
                        ┌──────────────────────────────┼────────────┐
                        ↓                              ↓            ↓
                  ┌───────────┐              ┌───────────┐  ┌───────────┐
                  │ Node 1    │              │ Node 2    │  │ Node 3    │
                  │ (Windows) │              │ (Mac)     │  │ (Linux)   │
                  └───────────┘              └───────────┘  └───────────┘
```

**适用场景**：
- 大规模并发测试
- 多平台兼容性测试
- 企业级CI/CD

## 推荐实现：客户端代理模式

根据您的需求，我们实现**方案二：客户端代理模式**。

### 架构设计

#### 1. 后端服务器（调度器）

**职责**：
- 创建测试任务
- 分配任务到可用的客户端代理
- 接收测试结果
- 生成测试报告

**不需要**：
- ❌ 不需要安装浏览器
- ❌ 不需要安装WebDriver
- ❌ 不需要执行UI操作

#### 2. 客户端代理（Agent）

**职责**：
- 连接到后端服务器
- 获取待执行的测试任务
- 在本地启动浏览器
- 执行UI自动化操作
- 上传执行结果和截图

**需要**：
- ✅ 安装浏览器（Chrome/Firefox）
- ✅ 安装WebDriver（或自动下载）
- ✅ 安装Agent程序

### 工作流程

```
1. 测试人员在Web界面创建UI测试
   ↓
2. 后端创建测试任务（状态：待执行）
   ↓
3. 客户端Agent轮询/监听新任务
   ↓
4. Agent获取任务并标记为执行中
   ↓
5. Agent在本地启动浏览器
   ↓
6. Agent执行UI操作步骤
   ↓
7. Agent截图并收集日志
   ↓
8. Agent上传结果到服务器
   ↓
9. 服务器更新任务状态和生成报告
   ↓
10. 测试人员在Web界面查看结果
```

### 技术实现

#### 后端API接口

```java
// 1. Agent注册接口
POST /api/agent/register
{
  "agentId": "agent-001",
  "hostname": "user-pc",
  "os": "Windows 10",
  "browser": "Chrome 120",
  "status": "online"
}

// 2. 获取待执行任务
GET /api/agent/tasks/pending?agentId=agent-001

// 3. 更新任务状态
PUT /api/agent/tasks/{taskId}/status
{
  "status": "running",
  "startTime": "2026-01-28T12:00:00"
}

// 4. 上传执行结果
POST /api/agent/tasks/{taskId}/result
{
  "status": "passed",
  "duration": 5000,
  "logs": "...",
  "screenshot": "base64..."
}
```

#### 客户端Agent程序

**技术栈**：
- Java/Python/Node.js（跨平台）
- Selenium WebDriver
- HTTP Client

**核心功能**：
- 连接管理
- 任务调度
- 浏览器控制
- 结果上传

### 部署方式

#### 服务器端（Linux）

```bash
# 不需要安装浏览器和WebDriver
# 只需要运行后端服务
java -jar ai-atg-backend.jar
```

#### 客户端（Windows/Mac/Linux）

**方式1：自动安装脚本**

```bash
# Windows
install-agent.bat

# Mac/Linux
./install-agent.sh
```

**方式2：Docker容器**

```bash
docker run -d \
  -e SERVER_URL=http://your-server:19080 \
  -e AGENT_ID=agent-001 \
  ai-atg/agent:latest
```

**方式3：桌面应用**

- 提供图形界面的Agent程序
- 一键启动/停止
- 实时查看执行状态

### WebDriver下载方式

#### 自动下载（推荐）

Agent程序内置WebDriverManager：

```java
// 首次启动自动下载
WebDriverManager.chromedriver().setup();
```

#### 手动下载

平台提供下载页面：

```
/downloads
  ├── chrome-driver-win64.zip

  ├── gecko-driver-mac64.zip

  │   └── geckodriver.exe

```

### 安全考虑

1. **Agent认证**
   - Agent使用Token认证
   - 定期刷新Token

2. **任务权限**
   - Agent只能获取分配给它的任务
   - 任务隔离

3. **网络安全**
   - HTTPS通信
   - 防火墙配置

4. **资源限制**
   - 限制Agent执行时间
   - 限制截图大小
   - 限制日志长度

### 监控和管理

#### Agent状态监控

```
/admin/agents
  - 在线Agent列表
  - Agent健康状态
  - 执行中的任务
  - 历史执行统计
```

#### 任务调度策略

- **轮询调度**：平均分配
- **优先级调度**：高优先级任务优先
- **亲和性调度**：指定Agent执行
- **负载均衡**：选择空闲Agent

### 对比总结

|  | 服务端执行 | 客户端代理 |
|---|---|---|
| 服务器安装浏览器 | ✅ 需要 | ❌ 不需要 |
| 客户端配置 | ❌ 不需要 | ✅ 需要 |
| 服务器负载 | 🔴 高 | 🟢 低 |
| 环境一致性 | 🟢 高 | 🟡 中 |
| 支持多平台测试 | 🟡 有限 | 🟢 支持 |
| 部署复杂度 | 🟢 简单 | 🟡 中等 |
| 适合场景 | CI/CD | 人工测试 |
